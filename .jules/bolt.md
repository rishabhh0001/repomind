## 2024-09-17 - [Graph Serialization Performance Bottleneck]
**Learning:** Large graph serialization using SQLAlchemy `selectinload` for relationships (like Edges source/target) can be highly inefficient and prone to `MissingGreenlet` errors in async contexts. The database is queried efficiently, but the overhead of ORM relationship resolution on thousands of rows causes noticeable slowdowns.
**Action:** When serializing large graphs or many interconnected records in SQLAlchemy, avoid `selectinload` for relationships needed only for serialization. Instead, pre-fetch all needed base records (like symbols) in one query, build an explicit O(1) python dictionary mapping by ID (`symbols_by_id = {s.id: s}`), and manually resolve foreign keys (`symbols_by_id[edge.source_id]`) in memory.
